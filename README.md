# Панели профиля организации

Генератор живой статистики для страницы `github.com/mottt-hub`. Собирает
активность **приватных** репозиториев через GitHub API, рендерит SVG-панели и
коммитит их обратно в этот репозиторий; `profile/README.md` показывает их через
`<picture>`.

## Зачем свой генератор

Все девять репозиториев организации приватные. Готовые сервисы
(`github-readme-stats`, streak-карточки и подобные) читают только публичную
активность, а положить токен в публичный README нельзя — они показали бы нули.
Собственный генератор в GitHub Actions читает приватные репозитории по токену из
secrets и заодно даёт полный контроль над оформлением.

## Токен — что создать и куда положить

Нужен **classic** personal access token со скоупом **`repo`**.

1. <https://github.com/settings/tokens> → **Generate new token (classic)**.
2. Имя: `mottt-hub org stats`. Срок: 1 год (после истечения панели замрут —
   workflow упадёт с явной ошибкой, а не покажет нули).
3. Отметить **`repo`** целиком. Больше ничего не нужно: workflow только читает.
   Скоуп `read:org` отдельно включать не требуется — `repo` его покрывает для
   чтения репозиториев организации.
4. Если в организации включён SSO — на странице списка токенов нажать
   **Configure SSO → Authorize** для `mottt-hub`, иначе приватные репозитории
   останутся невидимыми.
5. Положить в **этот** репозиторий: `Settings → Secrets and variables → Actions
   → New repository secret`, имя — **`ORG_STATS_TOKEN`**.

Fine-grained токен тоже работает, но требует ручной выдачи доступа каждому
репозиторию (`Repository access → All repositories` в организации `mottt-hub`,
разрешения `Contents: Read-only` и `Metadata: Read-only`) и повторной выдачи для
каждого нового репозитория. Classic-токен со скоупом `repo` покрывает всю
организацию автоматически — поэтому он и выбран.

Встроенный `GITHUB_TOKEN` для этой задачи **не подходит**: он ограничен
репозиторием, в котором выполняется workflow, и не видит остальные репозитории
организации.

## Защита от утечки

Панели публичные, исходные репозитории — нет. Сообщения коммитов это
единственный свободный текст, который переходит из приватного в публичное, и он
проходит через `tools/lib/redact.mjs` перед попаданием в SVG:

- Правило по умолчанию — **запрет**: токен публикуется, только если выглядит как
  обычная проза или узнаваемая лексика кода. Всё остальное становится `•••`.
- Явные запреты: IP-адреса, имена хостов на реальных TLD, URL, e-mail, пути в
  файловой системе, `host:port`, присваивания вида `KEY=value`, hex/base64-блобы,
  префиксы ключей (`ghp_`, `sk-`, `AKIA`, `eyJ`), PEM-маркеры.
- Эвристика на «похоже на ключ»: длинный токен, смешивающий буквы и цифры и
  часто меняющий регистр (так отлавливается пароль вида `62T16M38bUA3`, который
  не подходит ни под один явный шаблон).
- Контекстное правило: если в сообщении есть слово из чувствительного словаря
  (`пароль`, `токен`, `нода`, `secret`, `host`…, с учётом русских словоформ), то
  **любой** значение-подобный токен в этом сообщении вырезается — секрет часто
  стоит не сразу за ключевым словом.
- Если после фильтрации от сообщения ничего осмысленного не осталось, вместо
  огрызка публикуется `— скрыто —`.

`tools/test-redact.mjs` фиксирует это тестами: 15 сообщений с реальными утечками
должны быть вырезаны, 10 настоящих сообщений из истории организации — пройти без
изменений. Workflow запускает тесты **до** рендера, поэтому регрессия
останавливает сборку, а не публикуется.

Сырые данные (`tools/data.json`) содержат неотфильтрованные сообщения и внесены
в `.gitignore`.

## Локальный запуск

```bash
export GITHUB_TOKEN=$(gh auth token)
node tools/test-redact.mjs   # фильтрация
node tools/fetch-data.mjs    # API  → tools/data.json
node tools/render.mjs        # data → profile/assets/*.svg
node tools/preview.mjs       # локальные страницы для просмотра
```

`fetch-data.mjs` кэширует данные в `tools/data.json`, поэтому правки оформления
проверяются повторным запуском одного `render.mjs` — без обращений к API.

`preview.mjs` собирает страницы на настоящих фонах GitHub (`#0d1117` и `#ffffff`)
в трёх режимах:

- `settled` (по умолчанию) — анимации доведены до конца. Детерминированно, и
  именно это состояние видит посетитель почти всё время; для оценки дизайна
  нужен именно он, а не случайный кадр в середине анимации.
- `playing` — анимации как есть, чтобы убедиться, что они действительно идут.
- `static` — анимации вырезаны полностью. Имитация рендерера, который не
  выполняет CSS-анимации: контент обязан остаться полностью видимым.

## Устройство

| Файл | Роль |
|---|---|
| `tools/fetch-data.mjs` | GitHub API → `tools/data.json` (с ретраями) |
| `tools/render.mjs` | пять панелей × две темы → `profile/assets/` |
| `tools/preview.mjs` | локальные страницы для визуальной проверки |
| `tools/lib/theme.mjs` | токен-контракт, OKLCH → hex, цвета языков |
| `tools/lib/svg.mjs` | панель, карточка, Signal Tick, типографика, анимации |
| `tools/lib/redact.mjs` | фильтрация приватного текста |
| `tools/lib/text.mjs` | измерение и обрезка текста, склонения, «3 дня назад» |

Зависимостей нет — только Node 22+ и стандартная библиотека.

### Оформление

Эстетика — **Platinum Cockpit**: холодный графит с одной тёплой нотой
(шампанское-золото), глубина через волосяную линию и внутреннюю световую
подсветку сверху, никакого свечения. Подпись — **Signal Tick**: один и тот же
2px акцентный маркер слева повторяется у каждого заголовка, карточки и строки
ленты.

Ограничения, продиктованные средой:

- SVG внутри `<img>` не может загрузить веб-шрифты, поэтому пара
  Unbounded/Onest/JetBrains Mono из исходного рецепта заменена системными
  стеками с полным покрытием кириллицы.
- Ширину текста нельзя измерить при сборке, поэтому `tools/lib/text.mjs` считает
  её по таблице средних ширин символов и обрезает с небольшим запасом.
- Анимации — CSS, а не SMIL: только так работает `prefers-reduced-motion`.
- Скрытое стартовое состояние живёт **только** в `@keyframes`, а элементы несут
  `opacity="1"` атрибутом. Рендерер, игнорирующий анимации, покажет готовую
  панель, а не пустую.

### Кэш картинок

GitHub проксирует картинки README через camo и кэширует их по URL. `render.mjs`
подставляет в ссылки `?v=<хэш>`, посчитанный от содержимого SVG: ссылка меняется
ровно тогда, когда меняется картинка. Отметка времени вместо хэша переписывала бы
README при каждом запуске по расписанию и засоряла историю пустыми коммитами.
